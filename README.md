# BOBO Auto Job：AI 求职填表工作台

把个人资料保存一次，为不同岗位准备不同简历，再让 Codex 帮你填写企业招聘网站。

这份说明书面向没有编程经验的用户。推荐使用 **Windows 10/11 + Edge + 本地 Codex 客户端**。按顺序做完“首次配置”，以后只需要双击打开工作台、登录招聘网站、向 Codex 发送一段话。

> 当前版本需要你人工登录企业网站、处理验证码并核对最终提交。不同网站的表单不同，AI 可能需要你补资料或确认选项。本文提供完整安装流程和检查方法，但不能保证每一个企业网站都能自动填写。

## 先看懂需要装什么

你会用到三个窗口：

| 窗口               | 用来做什么                                           |
| ------------------ | ---------------------------------------------------- |
| 本项目的资料工作台 | 填写公共资料、上传简历、选择设置、查看网页任务和报告 |
| Codex 对话窗口     | 向 AI 下达扫描、填写、继续和检查的指令               |
| Edge 浏览器        | 你人工登录企业网站，AI 在你授权后操作招聘表单        |

需要准备的东西如下。第一次配置完成后，不需要每天重新安装。

| 名称                                          | 是否必需   | 怎么获得                                                                                               |
| --------------------------------------------- | ---------- | ------------------------------------------------------------------------------------------------------ |
| Windows 10/11 电脑                            | 本教程必需 | 使用你自己的电脑                                                                                       |
| Microsoft Edge                                | 必需       | Windows 通常已有；没有则从 [微软官网下载](https://www.microsoft.com/edge/download)                     |
| Node.js 24.11 或更高版本                      | 必需       | 从 [Node.js 官网](https://nodejs.org/en/download) 安装；它负责运行本地工作台                           |
| 可正常使用的本地 Codex 客户端和账号           | 必需       | 从 [Codex 官方入口](https://developers.openai.com/codex/) 按你的设备安装、登录；先确认能正常与 AI 对话 |
| 本项目文件                                    | 必需       | 从本仓库下载 ZIP 并解压                                                                                |
| Playwright Extension 浏览器扩展               | 必需       | 在 Edge 安装，下文有链接                                                                               |
| Playwright MCP                                | 必需       | 下文通过 Codex 配置安装；首次连接会下载                                                                |
| Resume Workspace MCP                          | 必需       | 本项目自带，配置到 Codex 即可                                                                          |
| resume-application skill                      | 必需       | 本项目自带；用 Codex 打开项目文件夹后即可发现                                                          |
| Git、GitHub CLI、Python、Docker、VS Code、WSL | 不需要     | 普通用户不用安装这些软件                                                                               |

这里的 **MCP** 可以理解为“让 AI 使用工具的连接”。**skill** 可以理解为“教 AI 按什么规则做事的操作手册”。你不用学习编程，也不用购买额外的数据库服务。本项目本身不要求填写 OpenAI API Key；Codex 的登录方式、使用额度及费用取决于你自己的账号配置。

推荐使用电脑上的本地 Codex 客户端。仅在浏览器里打开 ChatGPT，或者只使用远端 Codex 云环境，不能直接套用这份本地安装教程。

## 首次配置：一步一步做

### 第 0 步：安装并登录本地 Codex

已经能在电脑上的 Codex 客户端正常对话，可以跳到第 1 步。

1. 打开 [OpenAI 官方 Windows 客户端说明](https://learn.chatgpt.com/docs/windows/windows-app)，点击页面中的 Windows 下载链接。
2. 按官方链接在 Microsoft Store 或安装程序中完成安装。不要从不认识的网站下载所谓的“破解版”。
3. 从 Windows 开始菜单打开安装好的客户端，按提示登录自己的账号。
4. 找到 **Codex** 的本地项目/对话入口。官方新版可能把 Codex 集成在 ChatGPT 桌面客户端里；请使用其中的 Codex 功能，而不是普通的网页 ChatGPT 对话。
5. 先发一句“你好，请用中文回答”，确认能收到回答。若客户端提示账号无权限、额度不足或需要完成登录，先按客户端提示解决，再继续本教程。

后文的“Codex”指具备本地项目、MCP 设置和 skill 能力的客户端。官方 Windows 安装入口见上面的说明；已安装的独立 Codex 客户端也可使用，只要具有这些功能。

### 第 1 步：安装 Node.js

1. 打开 [Node.js 下载页](https://nodejs.org/en/download)。
2. 选择 Windows 安装程序，版本必须是 **24.11 或更高**。大多数电脑选择 **x64 / .msi**；ARM 电脑选择对应的 ARM64 安装程序。
3. 双击下载的安装程序，按默认选项点“下一步”直到安装完成。保留“添加到 PATH”的默认选项。
4. 如果安装程序询问是否额外安装编译工具，普通用户不需要特意勾选。
5. 安装完成后，关闭并重新打开 Codex；如果仍提示找不到 Node.js，重启电脑。

**检查是否成功：** 按键盘 `Win + R`，输入 `cmd`，按回车。把下面这一行复制进去，再按回车：

```bat
node --version
```

显示 `v24.11.0` 或更高版本即可。然后再输入：

```bat
npm --version
```

显示一串版本数字即可。这个黑色窗口可以关闭。

### 第 2 步：下载并解压本项目

1. 打开 [本项目 GitHub 页面](https://github.com/NemophilistJohn/bobo-Auto-Job)。
2. 点击绿色 **Code** 按钮，再点 **Download ZIP**。
3. 找到下载的 ZIP，右键选择“全部解压”。**不要直接在 ZIP 里面运行文件。**
4. 为了后面的配置可以直接复制，建议把解压出来的项目文件夹放到：

```text
C:\bobo-Auto-Job
```

5. 打开这个文件夹，确认里面直接能看到 `打开工作台.cmd`、`package.json`、`README.md` 和 `scripts` 文件夹。

**注意：** 不能多套一层文件夹。正确的是 `C:\bobo-Auto-Job\打开工作台.cmd`，而不是 `C:\bobo-Auto-Job\bobo-Auto-Job-main\打开工作台.cmd`。你可以给解压出来的 `bobo-Auto-Job-main` 文件夹改名为 `bobo-Auto-Job`。

如果 C 盘不允许放文件，可以放到你有写入权限的位置。后面的配置示例使用 `C:/bobo-Auto-Job`；你需要把它改成实际位置，例如 `D:/我的软件/bobo-Auto-Job`。配置中的 `/` 是正常的，不要随意换成单个 `\`。

### 第 3 步：第一次打开工作台

1. 在项目文件夹里双击 **打开工作台.cmd**。
2. 首次打开会出现黑色窗口，自动下载组件并准备界面。保持网络连接，等待它完成。
3. 成功后，默认浏览器会打开工作台，地址是：

```text
http://127.0.0.1:4318
```

4. 确认左侧有“公共事实资料”“简历与岗位”“网页任务”“执行设置”。

看到这些页面就表示工作台启动成功。之后可以关掉黑色窗口，服务会继续在后台运行。电脑重启后，需要再双击一次。浏览器标签页关掉了也没关系，再双击会重新打开。

`127.0.0.1` 表示你自己的电脑；这不是一个需要注册账号的公网网站。工作台在默认浏览器打开即可，但**企业招聘网站请统一在 Edge 中打开**。

### 第 4 步：在 Edge 安装 Playwright 浏览器扩展

这一项很重要：扩展让 AI 连接到你已经登录的网站。

1. 打开 **Edge**，不要在其他浏览器里完成这一步。
2. 在 Edge 地址栏粘贴下面的扩展商店链接并打开：

[安装 Playwright Extension](https://chromewebstore.google.com/detail/playwright-extension/mmlmfjhmonkocbjadbfplnigmagldckm)

3. 如果 Edge 顶部提示“允许来自其他商店的扩展”，点击允许并确认。
4. 点击“添加至 Chrome”或类似安装按钮，再确认“添加扩展”。在 Edge 中出现“Chrome”字样是正常的，因为这里使用 Chrome 扩展商店。
5. 点击 Edge 右上角的扩展图标，在列表里找到 **Playwright Extension**。建议把它固定到工具栏，方便检查连接。
6. 如果商店无法打开，先解决网络访问问题。不要随意安装名称相似、来源不明的扩展。

**检查是否成功：** 在 Edge 地址栏输入 `edge://extensions/`。列表中应能找到 Playwright Extension，并且它的开关已打开。

这里需要的是 **Playwright Extension**，不是录屏扩展，也不是 VS Code 的 Playwright 插件。正常使用本教程的扩展模式，不需要另外执行 `playwright install` 下载测试浏览器。

### 第 5 步：把两个 MCP 连接配置到 Codex

先完成第 3 步，让本项目依赖安装完毕，再做这一步。你需要添加 **两个**连接：一个读取资料，一个操作 Edge。

Codex 不同版本的界面名字可能略有变化。优先在 **设置 → MCP 服务器 / MCP servers** 中寻找“编辑配置 / Open config.toml”。官方配置文件通常是用户目录下的 `.codex/config.toml`；如果你的客户端使用了自定义配置目录，以客户端打开的文件为准。

#### 5.1 打开配置文件

1. 打开 Codex 的 MCP 设置，找到编辑配置文件的入口。
2. 如果找不到入口，按 `Win + R`，输入 `%USERPROFILE%\.codex`，按回车。
3. 找到 `config.toml`，用记事本打开。**先复制一份备份，再修改。**
4. 如果 `.codex` 文件夹不存在，先启动并登录一次 Codex。如果文件夹存在但文件不存在，可以新建 `config.toml`；注意不要变成 `config.toml.txt`。在资源管理器开启“查看 → 文件扩展名”可检查后缀。

#### 5.2 复制下面两段到文件最末尾

保留文件中原有内容，不要全选覆盖。若已经有同名的 `[mcp_servers.resume_workspace]` 或 `[mcp_servers.playwright_edge]`，更新已有的一段，不要添加重复段落。

```toml
[mcp_servers.resume_workspace]
command = "node"
args = ["C:/bobo-Auto-Job/scripts/start-mcp.mjs"]
startup_timeout_sec = 60
tool_timeout_sec = 120
enabled = true

[mcp_servers.playwright_edge]
command = "cmd"
args = ["/d", "/c", "npx", "-y", "@playwright/mcp@0.0.83", "--extension", "--browser", "msedge"]
startup_timeout_sec = 120
tool_timeout_sec = 120
enabled = true
```

这里只需要核对一处：`C:/bobo-Auto-Job` 必须是你第 2 步实际保存项目的位置。不要把示例中的路径照抄到不同的文件夹。`start-mcp.mjs` 会确保 AI 和工作台使用同一个资料目录。

教程固定使用 Playwright MCP `0.0.83`，避免首次安装时不同版本的行为不一致。浏览器扩展会自行更新，其授权页面可能有所变化。

如果已有能连接当前 Edge 的 Playwright MCP，可以保留它，跳过第二段，只添加 `resume_workspace`。确认已有连接使用的是扩展模式，并且能够看到你授权的招聘页面；不要同时启动多个浏览器连接去操作同一批页面。

#### 5.3 保存并重新启动 Codex

1. 在记事本按 `Ctrl + S` 保存，然后关闭。
2. 完全退出 Codex，再打开。仅关闭一个对话标签页通常不够。
3. 打开 MCP 设置，确认两个服务都已启用。第一次启动 Playwright MCP 会联网下载，可能需要稍等。

如果 Codex 的添加界面支持“命令、参数、工作目录”分别输入，也可以按上面两段配置填写：命令对应 `command`，参数对应 `args` 中的各项。**不要把 `http://127.0.0.1:4318` 当成 MCP 服务器 URL 添加**：它是资料网页地址，本项目的 MCP 使用本地命令连接。

### 第 6 步：让 Codex 发现配套 skill

推荐使用项目自带的 skill，不用另行下载。

1. 在 Codex 中选择“打开文件夹 / 添加项目 / Open folder”。
2. 选择 **整个 `C:\bobo-Auto-Job` 文件夹**，不是 `src` 或 `scripts` 子文件夹。
3. 如有项目信任提示，确认这是你刚从本仓库下载的项目后按提示操作。
4. 在这个项目里新建一段对话。
5. 检查 skill 列表是否出现 `resume-application`。部分 Codex 版本可以在输入框输入 `$` 后搜索它；也可以直接发送下一步的检查指令。

skill 位于 `.agents/skills/resume-application/SKILL.md`。它会指导 AI 处理展开区域、多页表单、下拉选项和日期选择器，并要求填写后读取页面核验结果。

如果你想在其他项目里也使用它，可以把**整个** `resume-application` 文件夹复制到 `%USERPROFILE%\.agents\skills\` 下，然后重启 Codex。这是可选做法；新手只用当前项目即可，避免同时安装多份同名 skill。

### 第 7 步：连接 Edge，并做首次检查

1. 保持 Edge 开着，使用安装了扩展的那个 Edge 用户头像对应的窗口。不要使用 InPrivate 无痕窗口。
2. 在 Edge 打开工作台或一个普通网页。
3. 回到 Codex，将下面整段复制发送：

```text
请使用 $resume-application 做一次只读连接检查：
1. 通过 Resume Workspace MCP 读取工作台状态，列出简历名称和当前设置。
2. 通过 Edge Playwright MCP 列出当前授权的浏览器标签页。
3. 确认你能读取 resume-application skill。
不要填写、修改或提交任何网页，也不要读取账号密码。
如果有连接缺失，请告诉我具体是哪一个。
```

4. 第一次连接时，Edge 可能打开扩展授权页，请你选择一个允许 AI 操作的标签页并批准连接。按扩展页面显示的按钮操作。
5. 某些扩展版本会创建一个专属的**标签页组**。AI 只能看到该连接组里的页面：把要处理的招聘标签拖进这个组，或右键标签页 →“将标签页添加到组” →选择该组，再让 Codex 重新列出标签页。扩展版本不同，连接范围可能不同，以实际列表为准。
6. 如果 Codex 显示工具调用授权提示，按你希望允许的操作确认。

**检查是否成功：** Codex 能告诉你工作台当前没有简历或有哪些简历、当前设置，以及你刚授权的 Edge 页面标题。如果它只说“已连接”但没有实际读取结果，请要求它调用工具检查。

**默认不用设置扩展 Token。** 每次手动批准连接即可。扩展还提供免重复确认的 Token 设置，这是可选高级功能；新手先跳过，不要把 Token 发到 GitHub、截图或聊天里。

## 日常使用：从资料到填写

### 第 1 步：双击打开工作台

双击 `打开工作台.cmd`，打开 Codex，并继续在本项目里对话。保持 Edge 开启。

### 第 2 步：填写公共事实资料并保存

1. 点击工作台左侧“公共事实资料”。
2. 点击分类展开，填写你确定的真实信息。
3. 教育、实习、项目、奖项、证书、家庭成员等可以添加多段记录。
4. 不确定或不愿提供的内容可以留空，所有资料字段均为可选。
5. **点击页面右上角“保存”。** 没有保存的内容不会成为 AI 可用的公共资料。

这里放姓名、学历、实际经历、日期、证书等事实。自我评价、岗位亮点、求职简述放在下一步的简历变体中。网页搜索框可以搜索字段，例如“导师”“绩点”“血型”。

### 第 3 步：为不同岗位上传不同简历

点击“简历与岗位” →“上传简历”。例如，你可以分别准备“后端工程师”“Agent 开发”“网络安全”“运维”四份简历。

| 项目               | 怎么填写                                                                       |
| ------------------ | ------------------------------------------------------------------------------ |
| 简历名称           | 取容易识别的名字，例如“后端工程师－校招版”                                     |
| 目标方向           | 例如“Java 后端开发”                                                            |
| 岗位说明           | 粘贴岗位职责、任职要求，或写想突出的能力                                       |
| 主观内容与写作约束 | 粘贴已写好的自我评价、个人简述；也可写“突出系统开发经历，语气简洁，不夸大成果” |
| 简历文件           | 选择对应的 PDF、DOC 或 DOCX，再点击保存                                        |

简历名称和文件必须填写。单个文件上限为 20 MB。

**当前版本不会自动把 PDF/DOCX 全文解析成公共事实。** 上传文件主要用于保存原件与附件上传。为了让 AI 获得充分的岗位信息，请主动填写“岗位说明”和“主观内容与写作约束”；客观经历请填进公共资料。只上传一个文件，不代表 AI 已经理解里面所有内容。

### 第 4 步：设置 AI 怎么工作

在“执行设置”调整开关，点击右上角“保存”。建议第一次使用保持最终提交关闭。详细解释见下一节。

**先保存资料和设置，再绑定网页任务。** 任务绑定时会保存当时的资料、简历和设置副本。之后修改公共资料，不会自动改掉已经绑定的任务。需要更新时，告诉 Codex 使用最新资料重新创建任务，并停用旧任务，避免继续用旧信息。

### 第 5 步：人工登录招聘网站

1. 在安装了扩展的 Edge 窗口里打开各家企业招聘网站。
2. 自己注册、登录、处理验证码。
3. 打开你准备投递的岗位，最好进入简历填写页面。
4. 保留这些标签页。先拿一个网站试运行，再增加多个网站。
5. 如果扩展限定标签页组，把这些页面加入 Codex 已授权的组。

AI 不负责登录，也不会替你解决验证码。暂时留在登录页也可以扫描，但会被标记为“待人工登录”。

### 第 6 步：让 AI 扫描并生成网页表

1. 点击工作台“网页任务”。
2. 点击“请求扫描已打开网页”。
3. 切换到 Codex，复制发送：

```text
请使用 $resume-application 扫描我已经打开并授权的 Edge 招聘网页。
读取每个候选页面，识别企业、岗位和是否已进入可填写页面。
把扫描结果写入工作台的网页任务表，保留识别依据。
本次只扫描，不填写、不登录、不提交，也不要关闭我的标签页。
如果扩展只开放部分标签页，请列出实际能看到的页面并告诉我。
```

4. 如果 Edge 弹出连接授权页，按前面的连接步骤批准。
5. 回到工作台。它会自动刷新，也可以点击“刷新任务表”。

**重要：扫描按钮只是登记请求，不会自行唤醒 AI。** 你还需要把上面的指令发给 Codex。也可以直接在 Codex 请求扫描，AI 会通过 MCP 创建扫描请求。

网页表中会出现企业/页面、岗位、页面状态、识别依据与简历选择框。

| 页面状态   | 你下一步做什么                                              |
| ---------- | ----------------------------------------------------------- |
| 可填写     | 核对企业和岗位，为这一行选择对应简历，点击“绑定简历”        |
| 待人工登录 | 去 Edge 完成登录并进入表单，然后重新请求扫描                |
| 需检查页面 | 查看识别依据，人工打开正确表单，再要求 Codex 检查或重新扫描 |

四个方向的岗位可以分别绑定四份简历，不需要用一份简历填所有页面。当前表格没有删除历史页面入口，可能保留以前的扫描记录；请按本次企业、岗位和页面核对，并在对话里明确本次范围。

### 第 7 步：要求 Codex 开始填写

绑定后，工作台会创建包含资料副本的填写任务。向 Codex 发送：

```text
请使用 $resume-application，填写工作台中本次已绑定的任务。
本次范围是：这里写企业和岗位名称。
严格遵守每个任务保存的设置，客观资料缺失或选项有歧义时不要猜。
处理展开区域和后续页面，每完成一部分都重新读取页面核验。
遇到登录、验证码、缺少资料或无法确定的选项时暂停并告诉我。
不要最终提交。完成后把已填写、有疑问、空缺字段写回工作台报告。
```

把“这里写企业和岗位名称”替换成真实内容，例如“甲公司后端工程师、乙公司运维工程师”。首次运行建议只指定一个任务。

### 第 8 步：查看报告、补充、继续

在工作台网页任务下面找到任务，点击“填写报告”。

| 报告分组 | 代表什么                                                |
| -------- | ------------------------------------------------------- |
| 已填写   | AI 已重新读取页面，确认字段里出现了填写值，并记录了证据 |
| 有疑问   | 标签含义、固定选项、页面状态等无法确定，需要你核对      |
| 空缺     | 没有可用资料，或还需要你提供内容                        |

报告还会显示保存状态与页面检查范围。**已填写不等于已保存，更不等于已提交。** 如果报告说“尚未保存”“保存未核验”或“页面检查未完成”，请继续核对。

对于一个已暂停的任务，可以直接告诉 Codex：

```text
继续处理甲公司后端工程师任务。刚才的疑问我确认如下：……
这些补充只用于本任务，仍然不要最终提交。
请继续填写并更新报告。
```

想把补充长期保存时，在公共资料中心填写并保存，再要求 Codex 用最新资料重新创建任务。当前版本不自动刷新旧任务的资料副本。

### 第 9 步：自己核对并提交

回到企业网站，从基本资料到教育、经历和附件逐项检查，包括日期、学校、证书、简历版本。确认无误后，由你点击企业网站的最终提交按钮，并查看网站的提交成功提示。

## 设置开关怎么选

更改开关后必须点击“保存”。设置会在绑定时复制进任务，旧任务不自动跟随变化。

| 设置                     | 建议与实际作用                                                                                                                                    |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 自动撰写未匹配的主观字段 | 默认关闭。开启后可基于选定简历的岗位说明和主观内容起草自我评价等文字；不能生成学历、日期、证书或不存在的经历                                      |
| 客观事实项使用模糊匹配   | 默认关闭。开启后可做保持原意的固定选项适配，例如“山西省→山西”“身体健康→健康”“O型血→O型→O”。原值、选项和理由应记录在报告中；多个选项冲突时仍应暂停 |
| 允许保存草稿             | 默认开启。允许 AI 点网站的保存草稿按钮；保存结果仍需核验                                                                                          |
| 允许最终提交             | 默认关闭，建议保持关闭。开启也不等于立即提交，skill 要求最终提交前单独确认                                                                        |
| 允许覆盖网页已有内容     | 默认关闭。避免替换你之前填写的内容；有冲突时先向你确认                                                                                            |
| 自动上传附件             | 默认开启。允许上传选定简历附件；第一次使用若只想检查文字，可关闭                                                                                  |
| 失败重试次数             | 默认 2 次。用于指导 AI 重试，无法让不兼容的网站自动变得兼容                                                                                       |
| 界面语言                 | 中文、英文、日文，按喜好选择                                                                                                                      |

这些是 AI 工作规则和报告校验的一部分，网页仍由 Codex 调用浏览器工具操作。当前版本不是无人值守的一键批量投递系统。

## 遇到问题怎么办

| 你看到的情况                    | 按这个顺序处理                                                                                                                  |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 双击后提示找不到 Node.js        | 安装 Node.js 24.11+；重启电脑；重新检查 `node --version`                                                                        |
| 黑色窗口正在下载很久            | 首次下载需要网络。先等待；报错后保留错误文字，检查是否能访问 npm，再让 Codex 帮助排查                                           |
| 工作台没有自动打开              | 在浏览器地址栏手动打开 `http://127.0.0.1:4318`；仍打不开则重新双击，查看 `data/launcher.log`                                    |
| 端口 4318 被占用                | 先重启电脑再双击。如果仍出现，向 Codex 提供报错，由它检查占用来源；不要乱结束不认识的进程                                       |
| MCP 提示找不到 `node` / `npx`   | 完全退出并重新打开 Codex；仍失败时把配置中的命令换成安装路径，例如 `C:/Program Files/nodejs/node.exe`，或让 Codex 帮助检查 PATH |
| Resume MCP 启动失败             | 先成功运行一次工作台；核对 `scripts/start-mcp.mjs` 的绝对路径；确认项目没有改名或搬家                                           |
| 配置保存后 Codex 报 TOML 错误   | 检查重复的同名 MCP 段落、引号和路径；必要时恢复配置备份，只重新添加本教程两段                                                   |
| Codex 看不到 skill              | 确认 Codex 打开的是项目根文件夹，里面有 `.agents/skills/resume-application/SKILL.md`；重启并在该项目中新建对话                  |
| AI 打开了一个没登录的全新浏览器 | 浏览器 MCP 很可能没使用 `--extension`。核对配置，禁用重复的浏览器 MCP，重新连接安装了扩展的 Edge                                |
| AI 看不到我打开的全部网页       | 先让它列出实际授权的标签页；检查 Edge 用户头像、扩展连接和专属标签页组，把待投页加入该组后再扫描                                |
| 扩展商店没有安装按钮            | 确认在 Edge 打开商店，并允许来自其他商店的扩展。公司电脑可能被管理员禁用安装                                                    |
| 扫描一直显示等待                | 在 Codex 发送扫描指令；工作台不会自己启动 AI。连接失败可先取消请求，修好后重新请求                                              |
| 表格仍说待登录                  | 在 Edge 进入可填写表单，再重新扫描。不要只在登录成功后停留在企业首页                                                            |
| 修改资料后 AI 仍用旧值          | 已绑定任务保存的是旧副本。要求 Codex 使用最新资料重新创建任务，并明确停用旧任务                                                 |
| 上传了简历但 AI 不知道内容      | 当前不自动提取 PDF/DOCX 全文；把事实填入公共资料，把岗位说明和主观内容填入简历变体                                              |
| 报告为空                        | 绑定简历只是创建任务；还需要向 Codex 发送填写指令，并要求写回报告                                                               |
| 网页点击失败或日期控件不会用    | 要求 Codex 重新读取页面；仍失败时由你手动处理该字段，再让它核验并继续                                                           |

需要 AI 排查时，复制下面这段，并附上实际报错：

```text
请帮我排查 BOBO Auto Job 的连接问题。
我已经完成的步骤是：……
出现问题的位置是：工作台 / Resume MCP / Edge MCP / skill。
实际报错是：……
请先检查连接和文件路径，不要删除我的资料，不要操作招聘表单。
```

发截图或日志前，检查是否包含身份证号、联系方式、Token、密码等个人内容。只提供排查所需的部分。

## 备份、更新和卸载

### 资料保存在哪里

个人资料、简历附件、网页记录和任务保存在项目里的 **`data` 文件夹**。数据库文件为 `data/workspace.sqlite`，附件在 `data/files`。首次运行后这个文件夹会自动出现。

本地保存不意味着 AI 从不接触数据：执行填写时，Codex 会读取任务资料和网页内容，数据处理遵循你所用 AI 服务的规则。你可以不填写非必需的个人资料。数据库当前没有额外的应用层加密，请使用你自己的电脑和账号。

### 备份

最简单的办法：退出 Codex，重启电脑，在重新打开工作台前，把整个 `data` 文件夹复制到私人备份位置。这样可以避免复制正在写入的数据库。不要只复制一个 SQLite 文件，也不要把 `data` 上传到公开仓库。

### 更新

1. 先按上面的方法备份 `data`。
2. 退出 Codex 并重启电脑，避免后台服务仍使用旧代码。
3. 从 GitHub 下载新 ZIP，解压到一个新文件夹。
4. 把备份的整个 `data` 文件夹复制到新项目根目录。
5. 双击新项目的 `打开工作台.cmd`，让它重新安装组件和构建界面。
6. 如果项目路径改变，更新 Codex 配置里的 `scripts/start-mcp.mjs` 路径，并在 Codex 中打开新项目文件夹。

新手不要直接覆盖旧项目的 `node_modules` 或 `dist`；新文件夹安装更容易确认更新生效。

### 卸载与停止

- 关闭工作台标签页不会停止后台服务。退出 Codex 并重启电脑可停止当前本地进程；只要不再双击启动，它不会自动开机运行。
- 卸载时，先备份资料，再在 Codex MCP 设置删除本项目两个连接（已有的自用浏览器连接可保留）。
- 如果额外复制过用户级 skill，删除 `%USERPROFILE%\.agents\skills\resume-application`。
- 重启电脑后删除项目文件夹。Edge 扩展可以在 `edge://extensions/` 中移除。

## 给开发者的命令

普通用户可以跳过本节。

```powershell
npm ci
npm run dev
```

开发界面：`http://127.0.0.1:5173`；本地后端：`http://127.0.0.1:4318`。

```powershell
npm run check
npm test
npm run build
npm run start
```

MCP 为 STDIO 服务，Codex 按需启动；`node scripts/start-mcp.mjs` 会固定数据目录和工作目录。UI 按钮通过本地 API 登记扫描请求，Codex 协调资料 MCP 与浏览器 MCP，两个 MCP 不互相调用。项目的 skill 在 `.agents/skills/resume-application/`。

开发依赖里的 Playwright/CLI 用于界面测试，不能替代用户浏览器中的扩展连接。本项目不要求普通用户安装额外的终端 Playwright skill。
